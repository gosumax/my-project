# Перенесённый номер новой руки: DEV-исправление

Триггер: на Smoke12 строка «Дилер: Начинается новая рука» и следующий `#число` создавали два сообщения. Первичная причина в `parser_core/message_assembly.py`: HAND_HEADER считает любую строку, начинающуюся с `#` и цифры, новым началом; `group_rows` закрывает активное сообщение до проверки продолжения. Затем `scripts/normalize_messages.py` получает две группы и создаёт NEW_HAND и HAND_ID.

Независимое воспроизведение общей формы на DEV: полный RAW Smoke11, кадры 860 и 1580. Это материал разработки, не независимый test. SHA проверены и записаны в `experiments/dev_new_hand_wrap_regression_20260928_v1/replay.json`; OCR строк сохранён вместе с recognition_id в журнале. Обе строки каждой пары имеют одинаковый chat_epoch.

message_assembly_v6: следующий целиком читаемый `#число` становится продолжением только после единственной строки с явным префиксом Дилер/временем и точной фразой «Начинается новая рука», в той же сессии и эпохе. Чужая эпоха/сессия, «Рука #», посторонний хвост номера и самостоятельный номер не присоединяются. Продолжение остаётся inferred, сообщение PARTIAL; уверенность не повышена.

После объединения общий нормализатор раньше терял hand_number: ветка SYSTEM возвращала NEW_HAND без номера. candidate_ru_v6 читает чистый завершающий `#число` после фразы новой руки. Отсутствующее или неоднозначное значение остаётся None. Actor, amount и role при этом None.

Парный replay на неизменных DEV-строках: v5 72 сообщения, v6 70; изменились только две пары на 860/1580. Полный порядок row_id и recognition_id сохранён. В нормализации 70 событий; при переходе v5→v6 изменился только hand_number_candidate двух NEW_HAND, типы, actor, суммы, роли, статусы и порядок совпали. Оба события UNRESOLVED. Старые версии хранятся в журнале.

Повторная сборка/нормализация v6 не изменила ни одну таблицу SQLite. При первом повторе только справочные journal_counts отчёта сборки обновились после уже завершённой нормализации; содержимое кандидатов не менялось. На следующем стабильном повторе оба JSON побайтно совпали. Доказательство: `experiments/dev_new_hand_wrap_regression_20260928_v1/idempotence_v6.json`. Принудительное прерывание отдельно ещё не проверено.

Проверка: `python -m pytest tests/test_message_assembly.py tests/test_annotation.py tests/test_normalize_chat.py -q` — 32 passed, 3 subtests passed. Регрессии проверяют перенос, самостоятельный номер, другую эпоху/сессию, посторонний хвост, сохранение номера без денежной суммы и отсутствие угадывания двух номеров.

Smoke12 v4 не переписывался. Это исправление общей формы по DEV после диагностики test; нужна новая неиспользованная сессия для финальной независимой оценки. Ники/сырые строки не исправлялись; ни один номер или кадр не встроен в производственный код.
