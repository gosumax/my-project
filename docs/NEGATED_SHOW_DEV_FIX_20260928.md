# Отрицание показа карт: общий фикс на DEV

В candidate_ru_v4 фраза «не показывает» попадала в положительное правило «показывает». Результат становился SHOW, а слово «не» добавлялось к actor. Исправлено в candidate_ru_v5: отдельное правило отрицания обрабатывается раньше положительного SHOW, в том числе с переносом и несколькими пробелами. Денежные поля остаются отсутствующими; статусы проверки OCR и публикации не повышаются.

## Доказательство и причина

`parser_core/normalize_chat.py → normalize → scripts/normalize_messages.py → event_revisions`: normalize проверял подстроку «показывает» в списке PLAYER_ACTIONS без проверки отрицания. Всё перед началом этой подстроки становилось ником, включая «не».

Триггер найден при диагностическом сопоставлении по PNG Smoke12. Прежде чем менять код, общая ошибка воспроизведена на уже использованном DEV Smoke11, слот 01, кадр 790. Новый RAW-кадр декодирован из источника с SHA-256 `e27c1b349b647ab540a36ddcb85505baf518f8977289ce32b2a4a25f4a4d5835`. Полный PNG чата скопирован и визуально проверен: видно «не показывает» + «карты». Текст/ник из прежнего OCR сохранён как raw, ник по памяти не исправлялся.

Копии и before/after: `experiments/dev_negated_show_regression_20260928_v1/`. `dev_evidence.json` хранит происхождение, SHA PNG и отдельный обнаруженный конфликт: SHA старого каталога не совпал с байтами указанного файла. Поэтому старый crop не использовался как проверенное пиксельное доказательство; новый декодированный PNG сохранён независимо.

Старый raw `Дилер: ghbdtпfylhtq не показывает`:

- v4: action=SHOW, actor=`ghbdtпfylhtq не`.
- v5: action=NO_SHOW, actor=`ghbdtпfylhtq`.

Это исправление типа действия и границы ника. Точное написание ника остаётся непроверенным OCR-кандидатом.

## Проверка

`python -m unittest discover -s tests -v`: 31 тест, PASS. Новая регрессия проверяет отрицание, перенос между «не» и «показывает», несколько пробелов/регистр, отсутствие денежных полей и сохранение обычного положительного SHOW. Журнал: `experiments/dev_negated_show_regression_20260928_v1/tests.log`.

`normalizer_replay.json` содержит одинаковые raw-фрагменты, результаты старого/нового кода и SHA обоих файлов. Исправление не содержит условий по кадру, видео, столу или нику. Остальные строки не редактировались вручную.

На полном минутном DEV-окне 0–1799 оба нормализатора применены к тем же сохранённым OCR/сообщениям. Число событий 72→72, ID и порядок совпали; изменились ровно два события: SHOW→NO_SHOW и исключение «не» из actor. Суммы, роли, причины и статусы не изменились (26 CANDIDATE, 46 UNRESOLVED). Доказательство: `dev_journal_version_comparison.json`. Это проверка локальности исправления, а не измеренная точность всей последовательности.

## Версии и оценка

Полная копия исходного кода, конфигураций и tessdata для воспроизведения зафиксированного v4: `experiments/smoke12_baseline_code_snapshot_20260928_v1/`, проверена против baseline_lock до исправления. Журнал `runs/smoke12_frozen_baseline_slot1_20260928_v1` сохраняет результаты v4; запускать новый нормализатор в нём не следует.

Smoke12 не использовался для обучения или выбора порогов. Его диагностические ошибки стали причиной изменения общего правила, поэтому последующий результат v5 на том же Smoke12 нельзя объявлять независимой финальной оценкой исправления. Исторический замороженный split=test и манифест сохранены. Для финального независимого теста после правки нужна ранее не использованная сессия. Использование test записано в `annotation/smoke12_test_use_record_20260928_v1.json`.

Качество полного парсера, все ники/карты, покрытие эталона, HH и realtime этим исправлением не подтверждены.
