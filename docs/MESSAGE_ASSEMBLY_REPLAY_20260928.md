# Сборка строк чата: проверка на Smoke11

## Причина и путь данных

`crops/.../000001425_chat.png` → `track_chat_rows.py` / `row_track_v9` →
физические строки и raw Tesseract OCR → `scripts/assemble_messages.py` →
`parser_core/message_assembly.py:visible_start` / `group_rows` →
`scripts/normalize_messages.py` → `scripts/reduce_hands.py`.

На кадре 1425 стола 01 OCR уже содержал отдельные строки «Дилер: Раздаются
карты.», пять строк «Дилер: ... сбрасывает», «Дилер: ... повышает до» и
числовое продолжение `6000`. Сборщик v2 распознавал новое сообщение только
по времени или заголовку руки. При небольшом правом отступе он объединил
восемь строк в `message_7258325432dde63172724b90`. Нормализатор взял первый
тип `DEAL`, а отдельное повышение в этой группе пропало. Исходный чат и
строки показаны в
`runs/smoke11_gameplay_f1425_1f_v9/row_review/frame_000001425_table_01_rows.png`.

## Изменение

`message_assembly_v3` считает строку с префиксом `Дилер:` началом сообщения.
Строка без нового явного начала продолжает предыдущее сообщение в пределах
той же сессии стола и эпохи чата, независимо от правого отступа. Время и
заголовок руки остаются явными началами. Неявное продолжение получает причину
`CONTINUATION_WITHOUT_VISIBLE_START`; оно не становится проверенным сообщением.
Версия входит в ID нового сообщения. Старые версии остаются в журнале.

продолжение суммы даже при широком правом поле и запрет переноса через эпоху.

## Границы результата

Это проверка сборки на одном игровом кадре и пяти начальных кадрах. Нет
независимой визуальной разметки, проверки точности всех OCR-полей, доказанной
идентичности столов, START-стеков, денежной и карточной проверки. Никакие
`CANDIDATE` и `PARTIAL` здесь не являются `VERIFIED` HH. Для этапа 1 ТЗ
следующий необходимый шаг — замороженный независимо размеченный эталон и
сверка каждого видимого сообщения с событием или явной неопределённостью.
