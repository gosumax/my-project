# Пустое чтение видимой строки: исправление и повтор

## Доказательство

Текущий Tesseract `rus+eng`, `PSM 7` возвращал пустую строку для видимого
текста на некоторых исходных полосках высотой 16 px. На Smoke10, кадр 1800,
стол 01, полоска `000001800_016.png` показывает сброс; на столе 04 полоска
`000001800_018.png` показывает «делает чек». PNG не был пустым. Отказ был
на шаге `scripts/ocr_chat_pilot.py` → Tesseract. Повтор на **тех же пикселях**,
увеличенных до 3×, дал непустое чтение. Это доказывает зависимость результата
от подготовки изображения на данном наборе, не идеальную точность текста.

Исходный захват Smoke10 сохранён отдельно:
`runs/smoke10_layout_probe_f1800`, source SHA-256
`214ef3b3c2e6bf5d1f438b648db3261495281baf0b27a06cdb900f7b34b8c0b0`,
PTS `921600/15360` (60 с), 18 raw ROI. Все девять чат-кропов визуально
просмотрены; полные столы 01 и 09 проверены дополнительно. Геометрия
подтверждена только на этом кадре. Этот источник уже использован для
разработки исправления и **не является независимым финальным тестом**.

## Общая логика

- После пустого успешного первичного OCR строки выполняется один повтор:
  grayscale PNG → 3× LANCZOS → Tesseract `rus+eng`, `PSM 7`.
- Первичное чтение остаётся в журнале. Повтор — отдельная ревизия с
  `retry_of`, SHA исходного PNG, SHA подготовленного PNG, параметрами и
  политикой `EMPTY_PRIMARY_ONLY_V1`.
- Повтор применяется только к пустому первичному OCR строк `CHAT_ROW`;
  непустые чтения не заменяются. Полный чат и явно выбранный `PSM 6` не
  проходят эту политику.
- Кэш ищет первичное и повторное чтения по их конфигурации во всей истории,
  поэтому обычный повтор запуска не чередует пустую и увеличенную ревизии.
- `message_assembly_v5` собирает сообщения по выбранной последней ревизии.
  Любой фрагмент с повторным OCR добавляет `OCR_RETRY_UNVERIFIED` и сохраняет
  сообщение `PARTIAL`; событие остаётся `UNRESOLVED`.
- Если повтор тоже пустой, физическая строка получает отдельный
  `UNKNOWN_EVENT` / `OCR_MISSING`, а не исчезает внутри предыдущего действия.
- `candidate_ru_v4` добавляет обычную формулировку PokerDom «делает чек» и
  передаёт причину непроверенного повторного OCR в событие.

Для пользователя это означает: строка с видимым текстом получает попытку
повторного чтения; неудача явно зарегистрирована, исходные данные не
подставляются из ручного чтения.

## Предварительная проверка метода

`scripts/probe_unreadable_row_ocr.py` выполнен до включения политики. Он не
меняет журнал, сохраняет raw альтернативы, версии и хеши. На семи пустых
полосках повтор дал непустой текст 7/7. На 60 контрольных непустых полосках
raw текст поменялся в 41/60 случаев; два одиночных результата изменили
интерпретацию номера руки. Это не точность по эталону и не основание
заменять все непустые чтения увеличенными. Поэтому политика ограничена
пустым первичным OCR.

Файлы эксперимента: `experiments/ocr_upscale_probe_smoke10_f1800.json`,
`experiments/ocr_upscale_probe_smoke11_f1425.json`,
`experiments/ocr_upscale_probe_smoke11_5f.json`.

## Текущие сохранённые прогоны

| Прогон | Уникальные строки | Пустые первичные чтения | Пустые выбранные чтения после повтора | Сообщения / события | Окна рук / HH |
| --- | ---: | ---: | ---: | ---: | ---: |
| Smoke10, кадр 1800 | 157 | 2 | 0 | 127 / 127 | 10 `PARTIAL` / 0 |
| Smoke11, кадр 1425 | 157 | 3 | 0 | 128 / 128 | 9 `PARTIAL` / 0 |
| Smoke11, кадры 0–4 | 158 | 2 | 0 | 131 / 131 | 17 `PARTIAL` / 0 |

Каталоги:

- `runs/smoke10_f1800_retry_v1_ru_v4/`
- `runs/smoke11_gameplay_f1425_1f_retry_v1_ru_v4/`
- `runs/smoke11_nine_table_5f_roi_cal_retry_v1_ru_v4/`

Все 7 первичных пустых чтений сохранены. Все 7 повторов дали непустой raw
текст. Он не идеален: например, OCR сброса прочитал ник `svistremnya` и
лишние символы справа. Этот ник не исправлялся визуальным чтением.
Три повторных фрагмента игрового кадра Smoke11 вошли в два события, поскольку
«использует резерв» / «времени» — перенос одного сообщения. Все события с
повторными фрагментами имеют статус `UNRESOLVED`.

`ocr_retry_verification.json` каждого каталога фиксирует проверку:
исходные кадры/PTS/ROI/физические строки совпали с предыдущим прогоном;
все прежние записи OCR сохранены; проверены SHA-256 175, 175 и 875 PNG.
Каждый текущий физический row ID представлен одним фрагментом сообщения.
Старые каталоги прогонов не менялись.

Повтор после завершения этапов не добавил записей и не изменил SHA-256 семи
производных отчётов в каждом каталоге. Общие счётчики журнала включают
историю; текущие результаты находятся в `current_version_counts` отчёта
`pilot_run.json`. Строковые обзорные листы обновлены для текущих каталогов.

Тесты: `python -m pytest -q` — 30 passed. Проверены отсутствие потери пустой
строки, непроверенный статус повторного чтения, сохранность исходного PNG,
воспроизводимость увеличения и поиск первичного чтения после новой ревизии.

## Воспроизведение и ограничения

```powershell
python scripts/run_nine_tables.py --output runs\smoke10_f1800_retry_v1_ru_v4 --skip-capture
python scripts/run_nine_tables.py --output runs\smoke11_gameplay_f1425_1f_retry_v1_ru_v4 --skip-capture
python scripts/run_nine_tables.py --output runs\smoke11_nine_table_5f_roi_cal_retry_v1_ru_v4 --skip-capture
```

Нулевые пустые выбранные чтения подтверждены только на 157, 157 и 158
физических row-записях этих трёх пилотов; это не независимая тестовая выборка.
Нет независимого эталона точности ников,
сумм и событий. Идентичность столов, деньги, карты, START-стеки, полные HH
и realtime не проверены. Источники `PARTIAL`; PTS — время наблюдения.
Следующий приёмочный шаг этапа 1 — независимая визуальная разметка и exact
event / false accept / unresolved с числителем и знаменателем.
