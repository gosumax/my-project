# Smoke14 RAM pipeline: параллельный OCR и визуальные карты

Точка входа: `scripts/run_smoke14_ram.py`. Первый этап остаётся в
`parser_core/ram_first_stage.py`: декодирование, сравнение ROI, физические
строки, `stable_row_id` и crop rules не изменены для параллельности.

## Очереди

- `ParallelRowOCR` использует ограниченную очередь batch и отдельный
  `TinyChatClient` на worker. По умолчанию два worker, очередь 32 batch.
  Полные batch первого стола отправляются во время capture. Остальные
  отправляются после сортировки по исходному стабильному ключу, чтобы
  сохранить состав batch исторического OCR. Результаты связываются с
  `table_id:frame_id:source_span_index`, а итоговая timeline сортируется
  по `table_id, frame_id, row_index`. Полная потоковость OCR для всех девяти
  столов пока не достигнута.
- `VisualTileQueue` использует отдельный persistent VL worker, очередь
  размером 256 по умолчанию. Он получает узкие физические строки чата с
  карточными плитками. BOARD и SHOWDOWN связываются с такими строками
  только по порядку внутри того же кадра, сессии и эпохи; требуется
  ожидаемое число карт. Прямые board ROI в текущем пути VL не используются.
- Результаты VL хранятся в `visual_evidence.jsonl` вместе с исходным crop,
  SHA-256, table/session, frame/PTS, raw ответом модели и статусом.
  `UNRESOLVED` и `CONFLICT_BOARD_CONTINUITY` сохраняются явно.
  Они не меняют raw OCR timeline и не создают
  сертифицированную историю руки.

## Ограничения

Существующий `PaddleOCR-VL-1.5` с prompt `OCR:` часто возвращает только
ранги или неразбираемые символы на крошечных картах. Такой ответ не
превращается в карты. Для SHOW используется карточная плитка из строки
чата; сопоставление имени игрока с конкретным местом за столом ещё не
доказано, поэтому прямой `shown_cards` ROI места пока не читается.
Экспериментальный `board_tiles_fixed_chat_v1` также воздерживается, если
для ранга нет шаблона пикселей. Статус `RAW_UNREVIEWED` означает сырой
визуальный результат, а не принятый HH.

## Запуск

```powershell
python scripts/run_smoke14_ram.py --video video/smoke_14.mp4 `
  --baseline C:/ParserData/runs/smoke14_full_tiny_ssd_20260929_v3 `
  --frames 9971 --output runs/smoke14_parallel_vl_full_20260929 `
  --ocr-workers 2 --ocr-queue-size 32 --vl-workers 1 --vl-queue-size 256 `
  --node C:/nvm4w/nodejs/node.exe
```

Каждый measured run требует новый каталог. `--skip-vl` оставляет тот же
параллельный OCR и отключает визуальные запросы для контрольной пары.

## Измеренный полный прогон прежней маршрутизации

Приведённые ниже числа относятся к прогону, где VL дополнительно получала
прямые board ROI. Исходные журналы этого прогона сохранены. После перехода
на только чатовые кропы полная скорость и качество отдельно не измерены.

Каталог: `runs/smoke14_parallel_vl_full_20260929`. Проверка
`parity_audit.json` сопоставила итоговый JSONL байт в байт с
`runs/smoke14_rowid_v2_full_2/ordered_timeline.jsonl`:
SHA-256 обоих файлов
`c88a7b7d67060185a0daf96b13d9be23206323930700fc1079762c5e8193b11b`.
Первый этап: 9971 кадров, 9 столов, 2691 физических строк,
61 уникальный `HAND_ID`. Проверены SHA-256 всех 265 визуальных crop и
PTS всех 106 прямых board crop; ошибок в этой проверке нет.

Старый полный RAM-прогон занял 391,080 с, новый — 962,644 с.
Новый capture занял 364,481 с; OCR от первого запроса до последнего
результата — 942,205 с; VL — 939,546 с. Фактическое перекрытие работы
OCR и capture составило 13,629 с по времени процесса (22,984 с при
суммировании двух worker). Наблюдались 32 из 32 batch в OCR-очереди и
160 из 256 заданий в VL-очереди. Пиковая RSS всей группы процессов,
включая VL-модель, — 4767,7 МБ; пиковая сумма CPU — 175,5%.

Фактически выполнено 265 VL запросов: 106 к прямым board ROI и 159
к строкам чата с карточными плитками. 193 запроса связаны с BOARD,
24 с SHOWDOWN, 48 остались без близкого события; дополнительно есть
20 записей о событии без карточной плитки, которые не являются
запросами модели. 12 board и 12 showdown чтений получили
`RAW_UNREVIEWED`, 241 реальный запрос остался `UNRESOLVED`.
Прямой board ROI не дал ни одного полного набора карт; все 12 board
чтений получены из плиток чата. Полный прогон `PARTIAL_VISUAL`,
проверенных HH нет.

В `final_summary.json` данного прогона поле `vl_model_responses=285`
ошибочно включает 20 синтетических записей без ответа модели.
Счётчик в коде исправлен после запуска; доказанное число запросов в
`parity_audit.json` равно 265, исходная сводка сохранена без правки.

|---:|---:|---:|
| 1 | 38,809 | 0 |
| 2 | 39,910 | 0 |

Два worker оставлены как ограниченный default для одновременного OCR.
Этот короткий benchmark не доказывает ускорение от второго worker;
три и четыре worker оказались медленнее на измеренном окне.

Финальный `python -m pytest -q`: 107 тестов и 7 subtests прошли.
Результат подключения остаётся частичным: во время capture OCR работал
только 13,629 с, потому что исторический состав batch удерживает строки
остальных столов до окончания первого этапа; прямой showdown crop места
игрока не подключён без доказанного соответствия имени и места.
