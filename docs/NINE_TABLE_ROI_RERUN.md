# Smoke11: повтор с калиброванным чатом и проверкой полосок

## Источник и происхождение

Видео `D:\Проэкты\V2.0 PD\video\smoke_11.mp4` использовано только на чтение. Исходные профили `configs/nine_table_layout.json` и `configs/layout_847x404.json` не менялись. Отдельная копия калибровки `configs/chat_log_bottom_rois.json` задаёт нижнюю границу чата для каждого слота; её SHA-256 `a79427cf111c243cbff288813c85ea54f90864291d4d435b32139f029a5fec01` записан в `provenance/manifest.json` и в `runs/smoke11_nine_table_5f_roi_cal_v2/summary.json`.

Один PyAV-декодер сохранил исходные кадры 0–4: PTS `0, 512, 1024, 1536, 2048`, временная база `1/15360`, размер 2560×1440. Получены 45 PNG столов и 45 полных PNG чатов. Все 90 проверены по SHA-256. Папка `runs/smoke11_nine_table_5f_roi_cal_v2/roi_review` содержит десять листов: все девять столов и все девять чатов для каждого кадра. `roi_review.json` связывает каждый ROI с координатами и исходным PNG.

## Исправление нарезки строк

В исходном выделителе `physical_spans()` яркая вертикальная полоса прокрутки стола 05 соединяла текстовые строки. На кадре 0 получался один гигантский кроп высотой около 318 px. Общий выделитель теперь не учитывает правые 12 px **только для поиска границ строк**; исходный PNG сохраняет полную ширину.

Затем по просьбе пользователя каждая строковая полоска расширена до 16 px с зазором до соседних текстовых полос. Самая верхняя видимая полоса `00` на каждом столе и кадре исключена из `CHAT_ROW` и OCR независимо от её кажущейся читаемости. Полный чат остаётся сохранённым. Таблица `row_suppressions` хранит координаты и причину `FIRST_VISIBLE_ROW_EXCLUDED` для каждого исключения. Нумерация остальных полосок остаётся исходной: первая сохранённая — `01`.

Текущий выделитель — `row_track_v9`. Его чистый повтор из тех же 90 исходных PNG находится в `runs/smoke11_nine_table_5f_roi_cal_v9`. Предыдущие прогоны сохранены для A/B; их окна рук не являются текущим результатом. В `v9` — 45 записей об исключённой полоске (по одной на стол и кадр), 785 ROI строк, все 16 px высотой. Нет ни одного `*_000.png` для строк и ни одного пересечения сохранённой полоски с исключённой областью. SHA-256 всех 785 сохранённых полосок проверены при построении листов `row_review/`.

Проверка на другом моменте видео: кадр 1425, стол 01, PTS `729600 / 15360` (47,5 с). Из исходного видео сохранён полный чат с видимыми «сбрасывает» и «повышает до 6 000». В `runs/smoke11_gameplay_f1425_1f_v9/row_review/frame_000001425_table_01_rows.png` игровые строки нарезаны по одной физической строке; «повышает до» и `6 000` остаются двумя полосками для последующей сборки сообщения. Полоса `00` исключена на всех девяти столах, 9 причин сохранены в журнале. На этом кадре 157 оставленных строковых ROI, все высотой 16 px.

## Итог конвейера и границы вывода

Пятикадровый `v9`: 9 сессий слотов с `identity_status=UNRESOLVED`, 5 кадров, 875 наблюдений (90 исходных ROI и 785 полосок), 158 уникальных физических строк и OCR, 57 сообщений и событий-кандидатов, 17 окон `PARTIAL`, 0 экспортов HH. Все 57 событий имеют статус `UNRESOLVED`. Повтор производных этапов сохранил эти количества; перекрёстных ссылок события на сообщение чужого стола не найдено. Тесты проекта проходят.

Это проверка геометрии и маршрутизации на двух коротких отрезках, не эталон точности. Исключение `00` сознательно удаляет верхнюю видимую строку из OCR, сохраняя её в полном чат-кропе и журнале исключений. Нельзя делать вывод о полноте событий, идентичности столов, правильности OCR или готовых HH. `source_pts` — время наблюдения в видео, не доказанное время действия. Все окна рук остаются `PARTIAL`; проверки денег и карт не выполнялись. Время повтора из сохранённых PNG не отражает скорость полного видео-конвейера.

Воспроизведение: `python scripts/run_nine_tables.py --output runs\smoke11_nine_table_5f_roi_cal_v9 --skip-capture`. Подробности окон: `runs/smoke11_nine_table_5f_roi_cal_v9/partial_windows_review.md`. Каждый сохранённый ROI строки: `runs/smoke11_nine_table_5f_roi_cal_v9/row_review/row_review.json`.
