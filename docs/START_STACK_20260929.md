# START STACK: история и проверка правила post-forced

## Фактический путь данных

`capture_nine_tables.py` сохраняет table PNG и `frame_id`/PTS в журнал. Новый
`observe_start_stacks.py` параллельно читает только table-наблюдения, сверяет
SHA профиля ROI, выделяет 8 пар nickname/stack ROI на слот, сравнивает пиксели с предыдущим
состоянием каждого `(table_session, seat)`, и передаёт изменившиеся crops в
ограниченную очередь Tiny OCR. Capture/row tracking/chat OCR не ждут эту очередь.
Каждый результат содержит table context, seat, кадр, PTS/время, хеши, crop,
сырое OCR и confidence. Потерянный кандидат и ошибка OCR явно регистрируются.
Это **сырое визуальное доказательство**; рука и игрок устанавливаются только
при последующем сопоставлении с timeline.

`parser_core/start_stack.py` принимает первое надёжное числовое чтение стека
без обязательного overlay. Для PokerDom оно уже после списания всех доказанных
ANTE/SB/BB; их точные суммы прибавляются обратно независимо от кадра появления
строки OCR. `RAISE_TO` учитывает только дополнительный вклад, а добровольные
действия требуют отдельного доказательства времени. При неполных данных
результат остаётся `UNKNOWN`. Основной HH pipeline не сертифицирует руки из
этого отдельного proof.

## Уточнение 30.09.2026: геометрия и реальные руки

`configs/layout_847x404.json` задаёт для каждого из 9 слотов одинаковые ключи
`seat1`–`seat8` с парой `nick` и `stack` ROI. Observer теперь снимает обе
области с одного table PNG и сохраняет общий `table_context`, кадр и SHA
исходного изображения. Отдельный геометрический seat↔nickname механизм не
нужен. OCR ника остаётся проверяемым фактом, а не следствием геометрии.

`parser_core/stack_temporal.py` сопоставляет raw chat и эти наблюдения по
`table_id`, HAND_ID, кадру и seat. Списания считаются существующим
`HandStackTracker`. Временной порядок нельзя вывести из одного OCR текста:
для `CERTIFIED` требуется сохранённая пара overlay→числовой стек, совпавшие
ник/стек из одного table PNG, визуально проверенные события этого игрока,
хешированные table кадры, полная сумма forced posts и видимый банк. Сомнения
дают `UNKNOWN`.

Три ante, пропущенные RAM OCR в первой руке, внесены только в отдельный
манифест визуальной проверки с SHA кадра; raw timeline не изменён. Первое
чтение стека само по себе не принимается за момент списания. Аудитор
повторно проверил кадры и расчёт этих трёх мест. Это ограниченное
доказательство, а не сертификация всех рук или HH.

Полный проход observer по сохранённым table PNG Smoke14: 89 739 table-наблюдений,
6536 OCR-кандидатов, 6536 обработаны, максимум очереди 158/256, 0 потерь и
ошибок. Получено 3303 stack и 3233 nickname наблюдения. На 61 окне HAND_ID
отчёт показывает 488 возможных seat ROI: 3 `CERTIFIED`, 16 `PARTIAL_START`,
469 `UNKNOWN`; число уникальных игроков остаётся неизвестным. Причины и
индивидуальные строки находятся в
`runs/smoke14_start_stack_full_20260930_v1/start_stack_coverage_current.json`.
Проверенный proof пересобран непосредственно из полного observer и нового RAM
timeline: `reviewed_start_stack_proof_current.json` в той же папке.

Новый RAM прогон `runs/smoke14_rowid_stack_parity_20260930_v1` завершился
`COMPLETE`: 9971 кадров, 9 столов, 2691 строка, 61 уникальный HAND_ID,
2691 уникальный `(source_roi_change_id,row_index)`. С сохранённым эталоном
совпали состав и порядок ключей, HAND_ID, raw OCR и типы событий. Проверка
проводилась с `--skip-vl`, то есть для Tiny OCR и основного ordered timeline,
на который опирается START STACK proof.

## Нерешённые условия для сертификации всех игроков

1. Получить читаемый ник и стек для остальных мест и рук; геометрия ROI уже
   задаёт seat, но OCR может быть неразрешённым.
2. Получить полные и точные суммы ANTE/SB/BB и отдельно доказать время
   добровольных действий относительно stack frame. Сейчас event reducer пишет
   `seat_id=None`, `action_time_status=UNKNOWN`, `starting_stacks=UNKNOWN`.
3. Доказать границы рук и отсутствие пропущенных событий. Текущий reducer
   выдаёт частичные окна; число 61 из RAM timeline не доказывает 61 полную руку.
4. Для остальных мест получить независимое доказательство временного порядка
   и учёта списаний; полный Smoke14 сейчас честно оставляет их `UNKNOWN`.

## Повторный расчёт post-forced

На тех же сохранённых кадрах и неизменном RAM timeline независимо проверены
ещё десять seat в двух руках T01. Для каждого есть ручная проверка exact table
PNG, SHA, nickname и первого числового stack, проверенные forced posts в чате,
видимый банк 35 000, отсутствие добровольной ставки до stack и, где применимо,
совпадение с последним prehand стеком. Манифест:
`runs/stack_proof_review_postforced_20260930.json`; proof:
`runs/smoke14_start_stack_full_20260930_v1/reviewed_start_stack_proof_postforced.md`.

Полный отчёт: 13 `CERTIFIED`, 16 `PARTIAL_START`, 459 `UNKNOWN`. Прежние 388
`TEMPORAL_ORDER_UNKNOWN` были общим остаточным классом: 10 стали `CERTIFIED`,
94 перенесены в `ACTION_ACCOUNTING_UNKNOWN`, 242 — в
`EVIDENCE_REVIEW_MISSING`, 13 — в `NICKNAME_OCR_UNKNOWN`, 26 — в
`FORCED_BET_EVIDENCE_UNKNOWN`; 3 остались `TEMPORAL_ORDER_UNKNOWN` из-за
распознанного `RAISE_TO` до первого числового стека. Остальные 385 не имеют
распознанного добровольного действия до этого стека, но требуют других
доказательств. Сравнение:
`runs/smoke14_start_stack_full_20260930_v1/start_stack_before_after_postforced.json`.

Вердикт по START STACK: `FORCED_BET_TEMPORAL_AMBIGUITY_ELIMINATED=YES`,
`START_STACK_COVERAGE_IMPROVED=YES`. Полные HH этим не сертифицированы.
