# Атомарность RAW capture и возобновление

Отдельная проверка восстановления после фикса скролла воспроизвела первичную причину отказа: `scripts/capture_predeclared_windows.py::capture` вызывала add_frame и add_observation с отдельными автокоммитами. Жёсткое завершение после первого ROI кадра оставляло frame без второго ROI. `checked_resume_frames` обоснованно отказывала: `Incomplete stored frame 12; retain for audit`.

До фикса на первых 30 кадрах прежнего DEV Smoke11: после аварии 13 frames, 25 observations, OPEN; возобновление отказало. Неполный журнал сохранён: `runs/dev_capture_crash_before_20260928_v1`. Манифест выбора и frozen snapshot прежнего capture-кода сохранены в `experiments/dev_scroll_identity_20260928_v1`.

Теперь frame и все выбранные ROI входят в одну транзакцию, пакеты ограничены десятью кадрами. При обычной ошибке незавершённый пакет откатывается, источник остаётся FAILED; при жёсткой аварии SQLite откатывает его, предыдущие полные пакеты остаются OPEN для проверяемого resume. Уже записанные PNG сохраняются и повторно сверяются по SHA; файлы не перезаписываются. Проверка resume на неполные старые кадры не ослаблена.

Та же авария после первого ROI кадра 12: сохранилось 10 frames / 20 observations, OPEN. Возобновление до 30 кадров совпало с непрерывным захватом по всем 15 таблицам, summary.json и SHA всех 60 PNG. Доказательства: capture_crash_before.json, capture_crash_after.json, маркеры аварии. Служебных времён в проверяемых таблицах нет. Ни OCR, ни события в этом эксперименте не создавались.

Регрессионный тест проверяет реальный rollback при ошибке записи ROI и отсутствие неполных frames в коммите. Полный набор: 58 passed, 3 subtests passed. Это отдельное общее исправление восстановления этапа 1, а не изменение row matching.

Первый захват расширения Smoke12 старым capture-кодом прерван после доказанного дефекта; 621 frame / 1241 observations, кадр 8620 имеет только один ROI. Он сохранён с interruption_note.json как аудит в `runs/smoke12_extension_raw_continuous_slot1_20260928_v1`. Для рабочего расширения выбран новый отдельный run v2; старый не очищался и не исправлялся вручную.
