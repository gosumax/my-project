# Chat OCR: right-edge trim and PaddleOCR-VL-1.5 fallback

The nine-table and one-table runners both use `scripts/ocr_chat_pilot.py` with
`configs/ocr_vl15_local.json`. This is a shared rule for every tracked `CHAT_ROW`;
there are no slot-specific branches.

The saved 228×16 crop remains unchanged. Tesseract reads a derived 216×16
crop after the rightmost 12 pixels are removed, enlarged 2× with Lanczos.
The optional empty-only retry uses the same trim at 3×. Each recognition records
the original crop hash, derived-input hash, transform and model version.

For a `Дилер:` player row, the full actor span before the action is checked.
An actor span containing Cyrillic or Latin `i/I/l/L` routes the same original
crop to a persistent, local PaddleOCR-VL-1.5 worker. This includes nicknames
that Tesseract has accidentally split with spaces.
An actor containing `?` or the replacement character also routes to VL.
Such symbols never count as a confirmed nickname: if they survive selection,
the event is `UNRESOLVED`. If VL removes them but disagrees with a known
Tesseract letter outside the `i/l/1` ambiguity, the VL candidate is shown
with `ACTOR_OCR_CONFLICT` and remains `UNRESOLVED`.
When both readers identify the same action and VL returns a Latin nickname
or a mixed nickname containing only visually identical Cyrillic/Latin letters,
the full actor span is substituted in a derived recognition. The Tesseract
action and amount are retained, while extra OCR tokens in the actor span are
removed. Original readings remain in the journal. A prior successful VL
reading of identical crop pixels with the same model and prompt is reused
across routing-policy revisions.
The message is marked `VL_NICKNAME_UNVERIFIED` and cannot become a complete
candidate from this reading alone.

Rows with the bright card-tile pattern also route to VL. The VL raw card text
is retained. A fixed-layout tile check separates the visible card panels,
compares each suit glyph with versioned templates in
`models/board_glyphs_v1.json`, and checks ranks against the VL reading.
If VL drops one rank, a clearly matched rank glyph can fill that position.
Only a complete, non-duplicate 3–5-card result with bounded glyph distances
replaces the selected text as a derived `BoardTiles` reading; otherwise the
raw VL text remains selected. The templates are based on saved Smoke12 crops
and remain unreviewed, so these readings are not independent ground truth.
Message assembly marks them as board fallback evidence. The current chat
normalizer does not turn that text into an accepted board event or certified
hand history.

The local model and its Python environment live in `D:\PD_BENCH`, outside this
project. Use `--vl-config` on either runner to select a different JSON config;
setting `enabled` to `false` keeps the trimmed Tesseract path and skips VL.
Missing or failed VL readings leave the Tesseract reading available and retain
an error recognition for review. The worker has a 600-second startup timeout,
a 130-second response timeout, and a 120-second generation deadline.

On the fixed-ROI 500-row chat benchmark, trimming plus 2× Tesseract was exact
on 32/42 manually referenced rows, compared with 25/42 for the original full
crop at 2×. Suspected scrollbar-tail artifacts fell from 36 to zero across
the 500 rows. This small manual reference set does not establish full-run
accuracy. The requested nickname predicate triggers 224/253 parsed player
rows in the VL-processed subset, so real nine-table runs can be substantially
slower; one model reading took roughly 3–4 seconds after warmup in the isolated
benchmark. The 9-slot smoke verified the common trim path, and a two-row
production-stage smoke verified a corrected `gen1usd` nickname and
`4 ♥ 2 ♦ K ♦` board text, both still marked partial/unverified.
